================================================================
  oneStep 앱 개발과정 및 방법
  히키코모리 사회복귀 지원 AI 퀘스트 앱
================================================================


1. 프로젝트 개요
----------------------------------------------------------------
oneStep은 사회적 고립(히키코모리) 상태에 있는 사용자가 작은 미션
(퀘스트)을 통해 점진적으로 사회에 복귀할 수 있도록 돕는 Android 앱이다.
AI가 사용자의 현재 상태·기분·주변 환경을 분석하여 적절한 난이도의
퀘스트를 추천하고, 퀘스트 완료 시 경험치와 함께 픽셀아트 동물 캐릭터를
해금하는 게임화(Gamification) 요소를 결합하였다.


2. 개발 환경 및 기술 스택
----------------------------------------------------------------
  [언어 및 프레임워크]
  - 언어           : Kotlin
  - UI 프레임워크  : Jetpack Compose (선언형 UI)
  - 최소 SDK       : API 28 (Android 9.0 Pie)
  - 타겟 SDK       : API 36
  - 빌드 시스템    : Gradle (Kotlin DSL)

  [백엔드 / 클라우드]
  - Firebase Authentication  : 사용자 인증 (Google OAuth 2.0)
  - Firebase Firestore       : 사용자 데이터 · 퀘스트 DB 실시간 저장
  - Google Gemini API        : AI 퀘스트 추천 및 필터링
  - 서울 실시간 도시데이터 API : 현재 위치의 날씨·혼잡도 조회

  [주요 라이브러리]
  - Navigation Compose       : 화면 간 이동 관리
  - Retrofit2 + Gson         : REST API 통신 (서울 API, Gemini API)
  - Google Play Services Location : GPS 위치 정보 수집
  - Kotlinx Coroutines       : 비동기 처리
  - Material Icons Extended  : UI 아이콘


3. 아키텍처
----------------------------------------------------------------
  MVVM(Model-View-ViewModel) 패턴을 기반으로 구성하였다.

  [계층 구조]
  ┌─────────────────────────────────────────────────┐
  │  UI Layer (Composable 화면들)                    │
  │  AuthScreen / MainScreen / ReceiveQuestScreen   │
  │  CollectionScreen / InitQuestionScreen 등        │
  ├─────────────────────────────────────────────────┤
  │  ViewModel Layer                                │
  │  AuthViewModel / MainViewModel                  │
  │  ReceiveQuestViewModel / CollectionViewModel    │
  ├─────────────────────────────────────────────────┤
  │  Repository / Util Layer                        │
  │  QuestRepository / FirestoreRepository          │
  │  LocationHelper / QuestRepository               │
  ├─────────────────────────────────────────────────┤
  │  Data Layer                                     │
  │  Firebase Firestore / Gemini API / Seoul API    │
  └─────────────────────────────────────────────────┘

  - StateFlow를 통해 ViewModel에서 UI로 단방향 데이터 흐름 유지
  - SharedPreferences로 진행 중인 퀘스트 상태를 앱 재시작 후에도 유지
  - 화면 전환은 NavController로 일원화하여 백스택 관리


4. 주요 기능별 구현 방법
----------------------------------------------------------------

  4-1. 사용자 인증 (AuthScreen, AuthViewModel)
  ─────────────────────────────────────────────
  - Google OAuth 2.0 + Firebase Authentication 조합 사용
  - GoogleSignInClient로 구글 계정 선택 → idToken을 Firebase에 전달하여
    FirebaseUser 생성
  - 최초 로그인 시 Firestore에 User 문서 자동 생성 (닉네임·나이 입력 후)
  - 이용약관 및 개인정보 처리방침 동의 체크 후에만 가입 완료 처리
  - 회원탈퇴 시 Firestore 데이터 삭제 → Firebase Auth 계정 삭제 순서로
    처리하여 데이터 잔류 없이 완전 삭제

  4-2. 초기 고립도 측정 (InitQuestionScreen)
  ─────────────────────────────────────────────
  - 최초 가입 시 6개 문항으로 고립도(isolated) 수치를 측정
    · 동거 가족 수, 식사 형태, 수면 시간, 외출 빈도, 히키코모리 자가진단,
      활동 시간대
  - 각 문항 응답을 가중 합산하여 0~100 사이의 고립도 점수 산출
  - 이후 퀘스트 난이도 결정 알고리즘의 핵심 입력값으로 사용

  4-3. AI 퀘스트 난이도 결정 알고리즘 (ReceiveQuest.kt)
  ─────────────────────────────────────────────────────────
  - 5가지 입력값을 바탕으로 적절한 퀘스트 난이도를 예측하는
    머신러닝 모델(Model_B) 탑재
    입력값:
      · 고립도 (0~100)
      · 현재 기분 (1~5단계)
      · 최근 10개 퀘스트 중 성공 횟수 (0~10)
      · 최근 10개 퀘스트 평균 난이도 (1.0~5.0)
      · 현재 티어 (0~7)

  - 모델 예측 결과를 기반으로 5개 난이도 레벨별 샘플링 비율을 계산
    예: 목표 난이도 2.6 → 난이도2: 62%, 난이도3: 28%, 난이도1: 10%
  - 비율에 따라 Firestore에서 퀘스트 20개를 사전 샘플링

  4-4. 실시간 환경 데이터 연동 (QuestRepository.kt)
  ─────────────────────────────────────────────────────
  - 서울 실시간 도시데이터 API를 Retrofit으로 호출
  - 현재 GPS 위치를 LocationHelper가 34개 서울 지역 중 가장 가까운
    지역으로 매핑하여 해당 지역의 데이터 조회
    조회 항목:
      · 날씨 (기온, 강수, 미세먼지)
      · 혼잡도 (여유 / 보통 / 붐빔 / 매우붐빔)
  - 조회 실패 시 "정보 없음"으로 대체하여 앱이 정상 동작하도록 처리

  4-5. Gemini AI 퀘스트 최종 선별 (QuestRepository.kt)
  ─────────────────────────────────────────────────────
  - 난이도 비율로 샘플링된 20개 퀘스트를 Google Gemini API에 전달
  - 프롬프트에 날씨·혼잡도 정보를 함께 첨부하여
    "오늘 환경에 가장 적합한 8개를 JSON 배열로 반환" 요청
  - Gemini 응답에서 인덱스 배열을 파싱하여 최종 퀘스트 8개 선별
  - API 호출 실패 시 샘플링된 목록에서 랜덤 8개로 대체(폴백 처리)

  4-6. 퀘스트 수행 및 결과 처리 (MainViewModel.kt)
  ─────────────────────────────────────────────────
  - 퀘스트 시작 시 퀘스트 정보를 SharedPreferences에 저장
    → 앱 재시작 후에도 진행 중인 퀘스트 복원
  - 퀘스트 완료 시 처리 순서:
    1) difficultyQueue(최근 난이도 이력) 업데이트
    2) questResultsQueue(성공/실패 이력) 업데이트
    3) progress(경험치) 누적
    4) 티어 승급 조건 확인 → EXPAMOUNT 배열 기준으로 자동 승급
    5) prevQuests에 완료 퀘스트 기록 추가
    6) Firestore 일괄 업데이트
  - 티어별 필요 경험치: [15, 48, 120, 230, 400, 650, 1000] XP

  4-7. 위치 권한 및 GPS 처리 (LocationHelper.kt)
  ─────────────────────────────────────────────────
  - 앱 최초 실행 시 ACCESS_FINE_LOCATION 권한 요청
  - FusedLocationProviderClient로 현재 GPS 좌표 수집
  - 34개 서울 주요 지역의 좌표 목록과 유클리드 거리 계산으로
    가장 가까운 지역명 반환 (currentAreaName 갱신)
  - 권한 거부 시 기본값 "강남역"으로 동작

  4-8. 픽셀아트 동물 시스템 (PixelAnimals.kt)
  ─────────────────────────────────────────────
  - 8종 동물(병아리~돌고래)을 25×25 픽셀 그리드로 직접 설계
  - 각 동물은 COLORS 리스트(최대 8~9색)와 PIXELS 2차원 정수 배열로 구성
    · PIXELS의 각 숫자 = COLORS 인덱스 (0=투명, 1=첫 번째 색 ...)
  - Canvas DrawScope의 drawRect를 픽셀 단위로 반복 호출하여 렌더링
  - 티어 해금 순서: 병아리(0) → 거북이(1) → 고양이(2) → 강아지(3)
                   → 파랑새(4) → 곰(5) → 말(6) → 돌고래(7)

  4-9. 메인 화면 파크 배경 (MainScreen.kt - ParkBackground)
  ─────────────────────────────────────────────────────────
  - Canvas API로 배경 전체를 직접 그림 (별도 이미지 파일 없음)
    · 하늘: 티어에 따른 색상 그라데이션
    · 잔디: 3겹 레이어로 원근감 표현
    · 장식물: 나무(티어1+), 울타리(티어2+), 태양·구름(티어3+),
              연못(티어4+), 꽃(티어5+)
  - 동물 배치 설계:
    · 하늘 구역(상단 1/3): 파랑새, 돌고래
    · 지상 구역(1/3 ~ 화면 하단 버튼 위): 나머지 6마리
    · 앞줄/중간/뒷줄 3단계 원근 배치로 자연스러운 공간감 연출
    · 겹침 방지: 픽셀 사이즈 3.5dp 기준 각 동물 약 87×87dp,
      좌우 3열(x: 0.02 / 0.38~0.58 / 0.66)으로 분리

  4-10. 컬렉션 화면 (CollectionScreen.kt)
  ─────────────────────────────────────────
  - 해금된 동물은 픽셀아트로 표시, 미해금 동물은 자물쇠 아이콘(🔒)
  - LazyVerticalGrid로 동물 카드 3열 그리드 레이아웃
  - 하단 스크롤에 완료한 퀘스트 이력(날짜·내용·난이도) 표시


5. 데이터 모델
----------------------------------------------------------------
  [User]
  - uid, email, nickname, age, gender
  - isolated         : 고립도 점수 (0~100)
  - isolatedCount    : 고립도 측정 횟수
  - prevQuests       : 완료 퀘스트 이력 리스트
  - difficultyQueue  : 최근 10개 퀘스트 난이도 이력
  - questResultsQueue: 최근 10개 성공(1)/실패(0) 이력
  - tier             : 현재 티어 (0~7)
  - progress         : 누적 경험치
  - termAgreed / policyAgreed : 약관 동의 여부

  [Quest]
  - questName  : 퀘스트 이름
  - difficulty : 난이도 (1~5)
  - index      : 퀘스트 고유 번호


6. 화면 흐름 (Navigation)
----------------------------------------------------------------
  [최초 실행]
  InitScreen → AuthScreen(Google 로그인) → SignupScreen(닉네임/나이/약관)
  → InitQuestionScreen(고립도 측정) → MainScreen

  [재실행]
  InitScreen → (자동 로그인) → MainScreen

  [메인 화면 내 이동]
  MainScreen ↔ ReceiveQuestScreen (퀘스트 받기)
  MainScreen ↔ MainQuestScreen    (퀘스트 수행 중)
  MainScreen ↔ CollectionScreen   (동물 컬렉션)
  MainScreen ↔ SettingScreen      (설정/로그아웃/탈퇴)


7. 보안 처리
----------------------------------------------------------------
  - API 키(Gemini, 서울 API)는 local.properties에 저장 후
    buildConfigField로 주입 → 소스코드에 하드코딩 없음
  - Firebase Security Rules로 본인 문서만 읽기/쓰기 가능하도록 제한
  - 이용약관 및 개인정보 처리방침을 가입 단계에서 필수 동의 처리
  - 개인정보는 Firebase 내에만 저장, 외부 서버 전송 없음


8. 예외 처리 및 폴백 전략
----------------------------------------------------------------
  - Firestore 오프라인: Source.SERVER 실패 시 Source.CACHE로 자동 전환
  - 서울 API 실패: "정보 없음"으로 대체하여 Gemini 프롬프트 전달 유지
  - Gemini API 실패: 사전 샘플링된 20개 중 랜덤 8개 반환
  - GPS 권한 거부: 기본 지역 "강남역"으로 대체
  - 퀘스트 역직렬화 실패: 개별 문서 스킵 후 나머지 정상 처리
